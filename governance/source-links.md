# 1. 第一性原理

## 1.1 证据链

```text
研究问题
→ 待验证主张
→ 来源
→ 来源中的可定位内容
→ 可信度与偏见评估
→ 独立交叉验证
→ 项目中的有限使用方式
→ 写入的故事/制作文件
→ 后续复核日期与失效处理
```

## 1.2 来源不是主张

错误写法：

```text
来源：某医院官网
结论：角色在 12 小时内必然康复。
```

问题：

- 没有记录网页到底说了什么；
- 没有说明角色具体情境是否适用；
- 没有区分一般信息、专业建议与虚构改编；
- 没有考虑剧情时间、个体差异与医疗风险；
- 没有记录谁把该结论写进剧本。

正确写法：

```text
主张：
某类轻度、非特异性损伤通常不应在短时间内完全恢复体力。

来源：
SRC-014，机构医学教育页面，访问于 [[日期]]。

可定位内容：
[[不超过必要长度的摘要，或页面章节标题/段落位置。]]

项目使用：
角色伤病在 24 小时内仍限制抓握与攀爬；
不以此页面决定具体诊断、治疗或现实医学建议。

状态：
需要专业顾问确认后，方可锁定为写实设定。
```

## 1.3 四类内容必须分开

| 类型 | 定义 | 能否直接写为事实 | 例子 |
|---|---|---|---|
| FACT | 可被可靠来源验证的外部事实 | 仅在已核验后 | “某制度要求某项流程” |
| INFERENCE | 基于多个事实作出的合理推论 | 不可伪装为事实 | “该流程可能造成延迟” |
| CREATIVE CHOICE | 为项目主动设计的虚构选择 | 可以写入 Bible，但须标注虚构 | “本片的港口系统每晚同步一次” |
| OPEN ASSUMPTION | 尚未核验、暂时使用的假设 | 不得锁定，不得作为关键因果唯一基础 | “角色或许能在此时抵达” |

状态标签：

```text
FACT_VERIFIED
FACT_PARTIAL
INFERENCE
CREATIVE_CHOICE
OPEN_ASSUMPTION
DISPUTED
SUPERSEDED
DO_NOT_USE
```

## 1.4 来源等级

> 来源等级不是自动真伪判定。
>
> 一手来源也可能带偏见、过时、被误读或不适用于当前问题。
> 二手来源也可能提供必要背景、线索与不同视角。

| 等级 | 来源类型 | 通常用途 | 默认限制 |
|---:|---|---|---|
| S1 | 官方原始文件、法律文本、正式数据库、原始数据、当事人记录 | 高风险事实、规则、日期、身份、公开决定 | 仍需确认版本、辖区、有效期和上下文 |
| S2 | 专业机构、同行评审研究、行业协会、权威教育机构 | 专业背景、方法、风险、通用规律 | 检查方法、适用范围、利益关系 |
| S3 | 有编辑流程的新闻、纪录片、专业采访、可靠行业媒体 | 事件背景、时效信息、多方观点 | 对关键事实回溯一手来源 |
| S4 | 专家文章、书籍、教学材料、专业博客 | 背景、术语、线索、创作参考 | 检查作者资质、发布日期、引用 |
| S5 | 社交媒体、论坛、营销页面、未署名文章、聚合站 | 线索、体验、视觉灵感 | 不单独支撑关键事实 |
| S6 | AI 生成内容、无法定位原文的转述、截图无来源 | 检索方向或内部草稿 | 不得作为事实来源 |

# 5. 交叉核验与冲突管理

## 5.1 最小交叉核验规则

| 主张风险 | 最低要求 |
|---|---|
| 低 | 一个身份可验证、适用且较新的来源；记录限制 |
| 中 | 两个相互独立的可信来源，或一个强一手来源 + 专业背景来源 |
| 高 | 原始/权威来源优先；独立交叉来源；适用范围核查；必要时顾问、法务或官方确认 |
| 真实指控、违法、医疗、法律、安全 | 不得靠单一媒体、社交媒体、AI 输出或营销资料锁定为事实 |

> 当一手来源不可获得时，不能悄悄降低标准。
>
> 必须标记：
>
> ```text
> FACT_PARTIAL
> 或
> OPEN_ASSUMPTION
> ```
>
> 并说明对故事、制作与发布的限制。

## 5.2 独立性检查

```text
两个来源看起来不同，不代表它们独立。

必须检查：
- 是否都引用同一个原始新闻稿、报告、采访或数据库；
- 是否由同一母公司、资助方、机构或倡议组织制作；
- 是否是聚合、转载、摘要或 AI 改写；
- 是否使用相同的未验证图片、视频或社交帖子；
- 是否共享同一错误、措辞或数据集。
```

## 5.4 冲突处理协议

```text
1. 先确认是否真的在谈论同一对象、时间、地域、定义与版本。

2. 回溯每个来源的原始材料、方法与日期。

3. 判断是：
   - 时间差异；
   - 地域/制度差异；
   - 人群/样本差异；
   - 定义不同；
   - 转载错误；
   - 真实不确定性；
   - 无法解决。

4. 对无法解决的关键冲突：
   - 不锁定为事实；
   - 改用虚构规则；
   - 删除依赖该事实的关键因果；
   - 或交由具备资质者复核。

5. 不得“挑选更符合故事需要”的来源作为真相。
```

# 10. 对抗式审查

## 10.1 来源检察官

- 这个来源是谁发布的，为什么发布？
- 它是原始来源、可靠二手来源，还是未经证实的转述？
- 它的发布日期、更新日期、适用地域、制度和人群是什么？
- 它是否清楚说明方法、数据、引用或证据链？
- 它是否有商业、政治、诉讼、名誉或意识形态利益？
- 是否存在更接近原始事实的来源？
- 这个链接是否只是另一个链接的复制、转载或 AI 改写？

## 10.2 主张检察官

- 本项目到底想证明什么具体主张？
- 来源直接支持该主张，还是只支持一个较弱、不同或更一般的说法？
- 我们是否从“可能”跳成“必然”？
- 我们是否把群体规律错误地写成个体必然经历？
- 我们是否把某地区/时期/制度的规则写成通用规则？
- 如果删除这个来源，这个主张还站得住吗？
- 如果不能，它是否承担了不应由单一来源承担的重量？

## 10.3 创作边界检察官

- 这条研究结论是否真的需要进入剧本？
- 它是否改变人物选择、世界规则、连续性或制作？
- 若不改变，是否只是无效设定堆积？
- 我们是在使用可验证事实，还是复制某来源的独特表达？
- 是否把“真实感”误当作“可以具体复刻现实对象”？
- 是否应该虚构化、合成化或删去高风险细节？

## 10.4 法务与安全检察官

- 是否涉及真实人物、可识别机构、品牌、声音、图片、地图、界面或文本？
- 是否会造成诽谤、隐私、肖像、版权、商标、合同或安全风险？
- 是否涉及医疗、法律、执法、未成年人、性、暴力、自残、药物、危险行为或歧视性表达？
- 来源是否足以支撑公开发布，而不只是内部创作参考？
- 是否已明确需要专业顾问或法务，而不是假装“查过网页就够了”？

## 10.5 版本检察官

- 来源是否仍可打开？
- 该页面是否已更新，结论是否变化？
- 本地摘录、截图、URL 和抓取日期是否匹配？
- 是否有人根据旧来源改过 Story Bible、剧本、分镜或资产？
- 是否需要发出 upstream notice？
- 旧结论是否已被标记为 `SUPERSEDED` 或 `DO_NOT_USE`？

# 13. 最终原则

```text
研究的目的不是让故事看起来“引用很多”。

研究的目的，是在需要真实感、专业性、历史性、
安全性、权利清晰度或事实可信度的地方，
知道自己到底知道什么、不知道什么、凭什么知道，
以及错误时会影响什么。

一个可用来源系统必须让团队随时回答：

这个主张来自哪里？
它支持到什么程度？
它不能支持什么？
谁验证过？
何时会过期？
它已经改变了项目中的什么？
如果它错了，下一步改什么？
```
