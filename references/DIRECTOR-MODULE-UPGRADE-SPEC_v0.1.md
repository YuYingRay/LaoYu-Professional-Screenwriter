# Director Module Upgrade Spec v0.1

> 文档状态：`DESIGN_DRAFT`
> 日期：2026-08-31
> 上游研究：`DIRECTOR-MODULE-SOURCE-AUDIT_v0.1.md`
> 对抗复核：2026-08-31，Codex 独立审查 + Claude Code Fabel 5 只读复核；本次只修设计文本。
> 规范效力：无。本文件描述候选升级，不修改当前 Skill 行为，不批准 P1A 继续生成。
> 设计目标：把剧本因果编译为镜头 Coverage、剪辑关系、Seedance 可执行输入与可验证成片。

## 1. 问题定义

当前流程已经具备 Scene Card、镜头功能、景别/轴线、单一主运动、关键帧、Prompt 和单镜 QC，
但真实项目暴露出一个序列级断点：

```text
Scene Card
→ Camera Direction Card
→ 15 秒生成
```

中间没有强制产出：

```text
Beat Map
+ Coverage Map
+ Edit Map
+ Segment Packing
```

因此一个包含多个信息与情绪节拍的15秒段落，可能被错误编译为一个持续跟拍镜头；画面能动、角色
稳定，却没有远中近景的叙事分工，也没有切点、反应和空间揭示。

## 2. 成功定义与非目标

### 2.1 成功定义

升级后的流程应让另一个执行者在不猜测导演意图的情况下回答：

1. 每个剧情节拍让观众新知道或新感到什么？
2. 哪些信息必须通过环境、动作、反应、细节或后果镜头呈现？
3. 每个镜头为什么存在，为什么从上一镜切到这一镜？
4. 人物与摄影机在空间中的起点、路径和终点是什么？
5. 一个15秒生成任务是单镜头还是多镜头序列？包含哪些 Shot？
6. 每张参考图承担什么角色，哪些控制图不得进入生产输入？
7. 成片是否真的完成了镜头语言，而不是只让 Prompt 看起来专业？

### 2.2 非目标

- 不把每个15秒段落强制规定为固定镜头数；
- 不要求所有场景凑齐远景、中景、近景和特写；
- 不建立大而全的摄影词典；
- 不把某个 GitHub Skill 整体嵌入现有 Skill；
- 不用自动评分替代余老师的观看判断；
- 不以升级导演模块为由重写已锁定故事、角色或安全边界；
- 不自动调用第三方 API，也不改变豆包 App 的人工生成方式。

## 3. 术语与对象模型

| 对象 | 定义 | 不等于 |
|---|---|---|
| `Scene` | 在相对连续时空中完成一个戏剧状态变化的逻辑场景 | 一次模型生成 |
| `Beat` | 欲望、信息、策略、反应或权力发生变化的最小剧情节拍 | 镜头或时间码 |
| `Sequence` | 为一个连续叙事任务服务的一组 Shot，可跨一个或多个生成段 | 单个 Scene 的同义词 |
| `Segment` | 一次模型提交产生的连续视频文件，例如15秒 | 必然只有一个 Shot |
| `Shot` | 观众感知为一次连续摄影的镜头单位，直到显式或可辨认的切换 | Prompt 中任意时间段 |
| `Frame` | 某一时刻的画面状态，可用于分镜、首帧或尾帧 | 完整动作或剪辑关系 |
| `Reference Asset` | 为身份、场景、道具、构图、动作、风格或声音提供约束的输入 | 越多越好 |

核心关系：

```text
一个 Scene 含若干 Beat
一个 Beat 可由一个或多个 Shot 表达
一个 Segment 可承载一个 Shot，也可承载有明确剪辑结构的多个 Shot
一个 Sequence 可由一个或多个 Segment 剪辑组成
```

## 4. 编译流程

### Stage 0：锁定上游与测试类型

输入：当前有效 Scene Card、剧本版本、资产版本、项目阶段与用户批准范围。

先声明：

- `PRODUCTION`：用于正片候选；
- `CONTINUITY_POC`：验证连续性，可转正前必须重审；
- `NON_CONTINUITY_POC`：概念测试，不得作为正片连续性证据。

若上游剧情状态、人物选择或安全规则不明确，停止在上游，不用摄影 Prompt 补写故事。

### Stage 1：Narrative Contract

每个待导演的 Scene/Sequence 先写：

```text
进入状态
人物当前欲望
可见阻碍
人物可见选择/行动
必须揭示的新信息
人物或观众的反应变化
退出状态
普通观众看完必须能回答的 1–3 个问题
```

若只有“氛围”“梦幻”“高级”等结果，不能进入镜头设计。

### Stage 2：Beat Map

每个 Beat 记录：

| 字段 | 含义 |
|---|---|
| Beat ID | 稳定编号，关联上游 SC/Script |
| Trigger | 什么动作、声音或信息触发本节拍 |
| Viewer Before | 节拍前观众知道什么 |
| New Information/Emotion | 节拍新增什么可见信息或情绪证据 |
| Character Action | 人物主动做什么，而非只被事件推动 |
| Result | 节拍结束后什么可见事实成立 |
| Importance | `ESSENTIAL / SUPPORTING / OPTIONAL` |

`OPTIONAL` Beat 在时长不足时可删除；`ESSENTIAL` Beat 不得被视觉奇观替代。

### Stage 3：Coverage Map

对每个 Beat 选择最小充分 Coverage：

| Coverage 功能 | 回答的问题 | 常见镜头起点 |
|---|---|---|
| Establish | 人物在哪里，阻碍与出口在哪里？ | WS/ELS/Master |
| Action | 人物具体做了什么？ | MS/MLS/Two-shot |
| Information/Insert | 关键线索、物体或变化是什么？ | CU/ECU/Insert/POV |
| Reaction | 这件事对人物意味着什么？ | MCU/CU/OTS reaction |
| Relationship | 人物与人物/动物/空间的距离和权力如何？ | Two-shot/OTS/Master |
| Consequence | 状态变化落在什么可见后果上？ | Result shot/hold/cutaway |

选择规则：

1. Coverage 由信息需求决定，不按固定套餐凑数。
2. 同一镜头可承担两个相容功能，但不得因压缩而让两者都不可读。
3. 重大揭示通常至少需要“信息 + 反应”；省略反应必须有明确审美与叙事理由。
4. 地点、人物或规则首次出现时，必须提供足够建立信息；不一定是大全景。
5. 若一个持续镜头能清楚完成全部功能，可以选择一镜到底，但不得用“连续”替代 Coverage。设计阶段必须提交
   `Timed Attention Path`：按时间段记录观众先看什么、获得什么可见事实、观看距离/景别如何变化、注意力如何转移。
6. 持续镜头只在上述路径覆盖全部 ESSENTIAL 信息、反应与后果时成立；无法在静态设计中证明时，回到多 Shot Coverage。

### Stage 4：Edit Map

每个 Shot 之间写显式 Cut Motivation：

| 类型 | 切镜依据 |
|---|---|
| New Information | 下一镜展示前镜无法读清的新事实 |
| Reaction | 从刺激切到人物反应或反切回来 |
| Eye-line | 沿人物视线切到其所见对象 |
| Action | 在动作过程中切换角度或景别 |
| Spatial Reveal | 通过拉开、遮挡或新角度揭示空间关系 |
| Emotional Emphasis | 在决定、迟疑或后果上改变观看距离 |
| Time/Place Change | 明确标示时空变化 |
| Sound Bridge | J Cut/L Cut 用声音连接因果或注意力 |
| Match | 动作、方向、位置、形状、颜色或声音匹配 |

每个切点还要记录：

```text
切出触发
→ 下一镜第一眼看见什么
→ 连续性匹配对象
→ 若模型不完成该切换，后期能否确定性补救
```

并把切点标为 `DIRECTOR_CRITICAL` 或 `OPTIONAL`。关键切点缺失且不能由已生成画面确定性补救时，
该 Segment 不得以“模型大致完成”为由通过；应重路由为独立 Shot、补充可剪 Coverage，或在预算耗尽后停止。

“为了丰富”“更电影感”“无缝转场”不是合法切镜依据。

### Stage 5：Shot Design

为每个 Shot 写：

```text
叙事功能
+ 主体与信息优先级
+ 人物 blocking（起点 → 动作 → 终点）
+ 景别、机位和构图
+ 空间轴、视线和动作方向
+ 一个主摄影运动或固定机位
+ 声音/台词触发
+ Cut in / Cut out
+ 连续性锚点
+ 失败降级
```

景别变化必须改变信息层级。例如从 WS 到 CU 应从“人物与环境关系”转向“人物反应或关键细节”，
不能只是机械放大同一张海报构图。

### Stage 6：Segment Packing

先完成 Shot 设计，再决定如何打包进模型任务。

| Route | 使用条件 | 默认策略 |
|---|---|---|
| `SINGLE_SHOT` | 连续动作、情绪停留、复杂身份/物理一致性比剪辑更重要 | 一次 Segment 一个 Shot；时间段只描述动作阶段 |
| `NATIVE_MULTI_SHOT` | 当前模型入口有可定位的多镜头执行记录，且 Shot 数量和动作密度与证据相近；或明确作为受限 POC | 一次 Segment 内显式列 `Shot 1/2/3...`，并提供分镜板或镜头构图参考；关键切点逐条验收 |
| `INDEPENDENT_SHOTS` | 需要独立重拍、精准构图或模型难以在单次生成中保持切镜 | 每个 Shot 独立生成，后期硬切/匹配剪辑 |
| `CHAINED_SHOT` | 同一动作超过时长，前后必须连续 | 以上一段真实尾帧或视频为下一段参考，不假设接缝自动消失 |
| `DETERMINISTIC_LAYER` | 字幕、UI、观察标记、魔法几何、可编辑图层或模型不稳定内容 | 从视频生成退出，在后期合成 |

打包约束：

- 不因入口允许15秒或30秒，就塞入更多剧情；
- 一个 Shot 默认一个主动作、一个视觉重点；
- 一个15秒多镜头 Segment 的镜头数量由动作密度与可读性决定，不设通用固定值；
- 多镜头的时间码是预算，不是帧级保证；
- 如果 Shot 独立性高于转场连续性，优先独立生成再剪辑。

`NATIVE_MULTI_SHOT` 的验证记录至少包含：平台入口、模型标签、日期、时长/画幅/音频、参考输入、
预注册 Shot/关键切点数量、实际可辨认 Shot/切点、不可执行项与原始输出路径。一条成功样本只证明可行性，
不证明稳定率；没有相近证据时默认 `INDEPENDENT_SHOTS`，除非该次任务明确标为 POC 并接受失败预算。

### Stage 7：Reference Input Map

每张参考图必须只有一个主要职责，必要时有一个次要职责：

| Role | 说明 |
|---|---|
| `IDENTITY` | 角色/动物身份、比例、服装或关键标志 |
| `LOCATION` | 场景空间、材质、入口出口、光向 |
| `PROP` | 关键道具形态与状态 |
| `STORYBOARD` | 有顺序的完整镜头构图与景别关系 |
| `START_COMPOSITION` | 某一 Shot 的起始画面 |
| `END_STATE` | 某一 Shot/阶段必须落到的可见终态 |
| `STYLE` | 色彩、材质和渲染语言，不承担角色身份 |
| `MOTION/CAMERA` | 只有模型和入口支持相应参考视频时使用 |

禁止：

- 为凑满上限上传无职责图片；
- 同一角色的多角度拼图被模型误读为多人时仍继续使用；
- 把轴线、箭头、文字、控制格栅和占位形状作为生产首帧；
- 把角色贴图放入透视、光向或接触关系不成立的场景首帧；
- 让 Style 图覆盖角色或场景的事实锚点。

### Stage 8：Prompt Compile

Seedance 多镜头 Prompt 候选结构：

```text
[[格式与路由]]
模型入口、画幅、时长、原生音频、多镜头或单镜头。

[[叙事结果]]
这一段必须让观众理解的状态变化。

[[参考绑定]]
逐张说明 @图片/视频/音频 的唯一职责。

[[全局锁定]]
角色身份、比例、服装、场景空间、光向、声音原则和禁止漂移项。

[[Shot 1]]
功能；景别/构图；blocking；主运动；声音；可见终态；切出触发。

[[Shot 2...]]
同上，并写明与上一镜的连接依据。

[[结束状态]]
下一 Segment 或剪辑必须继承的画面、动作、声音和信息状态。

[[有限约束]]
只保留高代价错误；不堆砌通用负面词。
```

Prompt 编译器不得：

- 新增上游不存在的剧情动作；
- 用风格词替代 Shot 功能；
- 把模型不支持的参数伪装成精确控制；
- 默认添加手持、变焦、环绕或复杂转场；
- 把“时间段”自动解释为“镜头”。

### Stage 9：Storyboard Gate

在视频生成前审查完整分镜板或独立关键帧：

1. 每个 Shot 的主体、景别和信息层级是否一眼可区分？
2. Shot 顺序是否与 Beat/Coverage/Edit Map 一致？
3. 人物位置、视线、动作方向和空间轴是否可剪？
4. 角色是否融入场景的透视、光向、遮挡、接触与尺度？
5. 是否混入观察线、文字、格栅、箭头、占位物或多余人物？
6. 竖屏手机尺寸下，远景是否仍能读到关键动作？

多镜头且存在人物/动物空间关系时，还必须附一项结构化证据：俯视 blocking 简图，或逐 Shot 的
`Camera Side / Subject Facing / Entry / Exit / Eye-line / Screen Direction (L/R/C)` 表。若有意越轴，必须写
越轴动机与重建空间关系的镜头；不能只用“轴线成立”自由文本自证。

静态分镜通过只能证明设计可读，不能证明模型会执行。

### Stage 10：Video Review and Edit

先审查叙事硬门，再审查连续性与技术瑕疵。通过的 Segment 才进入确定性剪辑、声音和字幕。

## 5. 候选 Director Sequence Card

现有 Camera Direction Card 保留单镜信息，但多镜头任务需要上层 Sequence Card：

```md
# Director Sequence Card

- SEQUENCE-ID / 版本：
- 上游 SC / SCRIPT / 资产基线：
- 测试类型：PRODUCTION / CONTINUITY_POC / NON_CONTINUITY_POC
- 总时长 / 画幅 / 目标模型入口：
- 进入状态 → 人物行动/选择 → 退出状态：
- 普通观众必须回答的问题：
- Beat Map：
- Coverage Map：
- Edit Map：
- 空间轴、入口出口、视线与动作方向：
- Timed Attention Path（仅持续镜头）/ Screen Direction Map（多镜头空间关系）：
- Segment Packing：
- Reference Input Map：
- 全局身份/场景/安全/权利锁：
- 声音策略与跨段桥接：
- 生成预算与停止条件：
- 确定性后期职责：
- 失败时回退到哪一层：Beat / Coverage / Shot / Asset / Prompt / Post
- 每个 ESSENTIAL Beat 的 Recovery Plan：邻镜替代 / hold / crop / cutaway / deterministic layer / 重路由 / NONE（若 NONE，标记生成关键路径）
```

### 5.1 每 Shot 最小字段

| 字段 | 必填条件 |
|---|---|
| Shot ID / Beat ID | 始终 |
| Narrative Function | 始终 |
| Viewer Gain | 始终：观众比上一镜多知道/感到什么 |
| Size / Angle / Composition | 始终 |
| Blocking Start → Action → End | 有人物、动物、道具动作时 |
| Axis / Eye-line / Screen Direction | 多镜头空间关系中始终；采用结构化 L/R/C 或 blocking 简图 |
| Primary Camera Move | 始终；固定机位也是选择 |
| Audio Trigger | 声音影响注意或剪辑时 |
| Cut-in / Cut-out Motivation | 多镜头 Sequence 中始终 |
| Continuity Anchors | 始终，数量按风险决定 |
| Reference Roles | 使用参考资产时 |
| Generation Route | 始终 |
| Failure Downgrade / Recovery Plan | 承担 ESSENTIAL Beat 的 Shot 始终；其他高价值或高风险 Shot |

## 6. Seedance 适配配置

### 6.1 能力事实与入口事实分离

| 层级 | 当前可用事实 | 使用规则 |
|---|---|---|
| Seedance 2.0 官方模型 | 最多 9 图/3 视频/3 音频；15秒多镜头音画；可理解文本分镜与摄影语言 | 可作为模型级设计上限，不保证每个平台暴露全部入口 |
| Seedance 2.5 官方模型 | 最长30秒叙事目标；更强参考、编辑、摄影和表演调度 | 具体账户、时长、输入数与编辑功能在生成前核验 |
| 豆包 App 当前项目入口 | 用户于 2026-08-31 确认 9 图、15秒、Seedance 2.0 Fast/2.0/2.5 可选；仓库内尚无冻结 UI 截图 | 作为当前项目的账户观察 `PARTIAL`；生成前复核 UI，不作为模型通用能力 |

不得把第三方 API 的字段、MuAPI 的能力或其他平台的时长写入豆包 Profile。

### 6.2 多图策略

推荐优先顺序：

```text
一张可读的完整 Storyboard
+ 必要角色身份参考
+ 必要场景参考
+ 必要道具/终态参考
```

不是默认把每个分镜格裁成独立图片，也不是默认凑满九张。若完整 Storyboard 中面板太小、角色身份
漂移或控制标记被渲染，再切换为独立 Shot/首尾帧策略。

### 6.3 适配器输出

每次生成前必须输出：

- 入口 Profile：模型、时长、画幅、音频、可用输入数量；
- 参考文件清单及角色绑定；
- Segment 内 Shot 顺序；
- Prompt 版本；
- 预期硬门；
- 本次是否消耗生成预算；
- 若失败，哪种证据允许重试。

若使用 `NATIVE_MULTI_SHOT`，还必须引用上一节要求的入口验证记录；官方宣传或“模型可选”本身不能替代执行证据。

## 7. 验收门禁

### G0：上游叙事门

通过条件：进入状态、人物行动/选择、退出状态和观众问题明确。
失败：需要 Prompt 发明剧情，或镜头只追求氛围。

### G1：Coverage 门

通过条件：每个 ESSENTIAL Beat 都有最小充分 Coverage；镜头功能可解释。
失败：只有运镜，没有定位、信息、反应或后果路径。

### G2：Edit 门

通过条件：多镜头任务的每个切点有动机和连续性匹配对象。
失败：Shot 只是独立漂亮画面，顺序可任意互换。

### G3：Storyboard/Input 门

通过条件：分镜可读，参考职责明确，角色与场景透视/光向/尺度成立，无控制标记污染。
失败：角色像贴图、空间关系错误、无职责图片或观察图进入生产输入。

### G4：Prompt 编译门

通过条件：Prompt 忠实编译批准的 Beat/Coverage/Edit/Shot，不新增剧情或伪参数。
失败：重新变成词库拼接，或把时间段假装成切镜。

### G5：成片叙事硬门

普通观众不读文档观看后，应能回答预注册问题。以下任一属于硬失败：

- 无法判断人物在哪里或为什么进入新场景；
- 重要角色/信息无因果地突然出现；
- 人物从陆地、海面、水下等空间无解释跳转；
- 关键刺激存在但缺少必要反应，导致意义不可读；
- 目标明确是多镜头叙事，但成片没有可辨认的信息层级变化；
- 目标是持续镜头，但成片没有执行批准的 Timed Attention Path，导致 ESSENTIAL 信息、反应或后果不可读；
- `DIRECTOR_CRITICAL` 切点缺失，且现有画面不能确定性补救；
- 轴线、方向或空间重构导致观众误解行动。

至少保留一份上下文隔离回答：审查者在观看前不得读取导演卡、Prompt、预期答案或失败归因；记录审查者类型
（人类/独立模型）、原始回答与时间。独立模型只能作为辅助证据，余老师保留最终审美和生产裁决。

### G6：可剪连续性门

检查角色身份、比例、服装、道具、人物位置、视线、动作方向、光向、声音和跨 Segment 接口。

### G7：技术与安全门

检查编码、时长、画幅、水印、错误文字、畸形、闪烁、儿童/动物安全和权利边界。

### 7.1 非阻断偏差

在 G5–G7 已通过且不影响身份、因果、安全或可剪性时，以下通常不单独触发重抽：

- 轻微头发、尾鳍、衣褶或环境微动差异；
- 切点与目标秒点有小幅偏移；
- 不破坏信息层级的景别微差；
- 不影响人物关系和空间理解的背景细节漂移；
- 风格偏好上的细小差异。

## 8. 停止与重试

通用原则，不把当前项目预算固化为全局规则：

1. 每个项目在生成前声明初始次数、总上限和高价值 Shot 上限。
2. 重试必须绑定可修机制，例如 Cut 未执行、参考角色冲突、Storyboard 不可读或 Prompt 密度过高。
3. 同一失败连续两次，停止同类重抽，回退到 Coverage、Shot、Asset 或 Segment Packing。
4. G5 硬门通过后，不为不影响叙事的轻微漂移继续抽卡。
5. 不能用其他镜头的成功抵消当前关键镜头的叙事失败。
6. 模型不稳定但后期可确定性修复时，优先退出生成队列。

P1A/P1B 30秒概念样片的候选预算建议为：每个15秒 Segment 初始1次；只有机制明确时再生成1次，
总上限4次。该数字仍需用户批准，不自动生效。

### 9.1 文档与行为测试

| T-DIR-01 | 单一情绪停留、适合一镜到底 | 不强制多镜头，不机械凑景别 |
