# 1. 第一性原理

镜头不是装饰性术语的集合，而是观众获得故事信息的路径。镜头设计必须依次回答：

```text
观众此刻必须理解什么变化？
→ 应站在谁的感知或权力位置？
→ 必须看见哪个动作、关系或后果？
→ 摄影机如何移动才让变化更清楚？
→ 这一运动能否由当前模型或拍摄条件稳定完成？
```

全局规则冲突按 `governance/control-plane-contract.md#71-规则冲突优先级` 裁决。本参考只定义镜头设计内部的取舍：

```text
安全、权利与技术事实
> 人物选择和场景因果
> 空间、视线与动作连续性
> 主体可读性
> 情绪节奏
> 视觉奇观
```

若删除某个运镜不损失信息、情绪或转场功能，就优先删除。若一个镜头只有“高级感”而没有
可验证的叙事结果，它不是导演方案。

## 1.1 四层分离

不要把不同层级混写成一串“运镜词”：

| 层级 | 决定什么 | 例子 |
|---|---|---|
| 叙事 | 观众理解的状态变化 | 吉米先停步，再呼叫成人 |
| 摄影 | 摄影机位置、角度、运动、焦点 | 眼平中景，沿角色右后方稳定跟移 |
| 剪辑 | 两个镜头如何连接 | 动作匹配、J Cut、L Cut、交叉剪辑 |
| 特效/后期 | 画面如何变形或合成 | 径向模糊、粒子、分屏、像素解体 |

“匹配剪辑”“溶解”“分屏”不是摄影机运动；“粒子拖尾”“伪微观细节”“未验证高帧率”
也不是模型必然执行的摄影指令。只有在工具和后期流程真实支持时，才把它们写入执行层。

# 2. 镜头导演工作流

## 2.1 对象与编译顺序

先分清层级，禁止把剧情时间段直接当镜头或把一次模型提交当作一个镜头：

| 对象 | 定义 | 不等于 |
|---|---|---|
| `Scene` | 同一主要时空中的戏剧单元 | 一次生成任务 |
| `Beat` | 信息、情绪、权力、目标或策略发生一次可辨认变化 | 自动切点 |
| `Sequence` | 为一个较大戏剧结果组织的一组 Beat 与 Shot | 单个视频文件 |
| `Shot` | 从一次切入到下一次切出之间的观看单元 | Prompt 时间段 |
| `Frame` | Shot 内的单帧或关键构图 | Shot 本身 |
| `Segment` | 一次模型提交产生的连续视频文件 | 必然只有一个 Shot |

关系固定为：

```text
Scene → Beat → Coverage → Edit → Shot → Segment → Prompt → Review/Edit
```

一个 Segment 可承载一个 Shot，也可承载经过批准的多 Shot 结构；一个 Sequence 可由一个或多个 Segment
确定性剪成。先设计 Shot，再决定如何打包 Segment，不能从模型时长反推剧情和镜头数量。

多节拍、多镜头、跨场景或完整短片必须先完成：

```text
Beat Map → Coverage Map → Edit Map → Shot Design → Segment Packing
→ Director Sequence Card 批准 → Camera Direction Card 批准 → 模型执行 Prompt
```

此顺序表示设计依赖与审查条件；当前有效批次委托可覆盖中间产物，无需逐卡再次询问。
按 `references/ai-production-handoff.md` §2.3 记录执行者、授权依据与范围，不能用自检伪造人工批准。

## 2.2 Coverage 与 Edit Map

每个 `ESSENTIAL Beat` 先写观众必须获得的变化，再选择最小充分 Coverage：

这些变化须回查当前完整场景剧本，不能只从已经压缩的制作简卡反推。在现有 Coverage 中
指出“必要信息 → 具体可见/可听证据 → 对应 Shot”；原来的选择依据、人物交流或后果
若被删去，按交接参考 §7.5 核对替代承载。标签齐全、景别不同、场景一致不等于信息已经传达。

| Coverage 功能 | 观众问题 | 常见起点 |
|---|---|---|
| Establish | 人物在哪里，阻碍与出口在哪里？ | WS/ELS/Master |
| Action | 人物具体做了什么？ | MS/MLS/Two-shot |
| Information | 关键线索、物体或变化是什么？ | CU/ECU/Insert/POV |
| Reaction | 这件事对人物意味着什么？ | MCU/CU/OTS reaction |
| Relationship | 人物与人物、动物或空间的距离如何？ | Two-shot/OTS/Master |
| Consequence | 状态变化落在什么可见后果上？ | Result shot/hold/cutaway |

Coverage 由信息需求决定，不按远中近特写套餐凑数；同一 Shot 可承担两个相容功能，但不得让两者都不可读。
重大揭示通常同时需要信息与反应。首次出现地点、人物或规则时必须建立足够空间信息。

持续镜头可以成立，但不能用“一镜到底”替代 Coverage。必须提交 `Timed Attention Path`，按时间段记录：

```text
观众先看什么 → 获得什么可见事实 → 观看距离/景别如何变化 → 注意力如何转移
```

若 `Timed Attention Path` 不能覆盖全部 ESSENTIAL 信息、反应与后果，就回到多 Shot Coverage。

每个切点写明：切出触发、下一镜第一眼信息、连续性匹配对象、后期能否确定性补救，并标记：

- `DIRECTOR_CRITICAL`：缺失会破坏因果、信息、反应、空间或可剪性；
- `OPTIONAL`：缺失不改变上述结果，可由现有画面吸收。

`DIRECTOR_CRITICAL` 切点未执行且无法确定性补救时，不得以“模型大致完成”通过。

多镜头空间关系还必须提交俯视 blocking 简图，或逐 Shot 的 `Screen Direction Map`：

```text
Camera Side / Subject Facing / Entry / Exit / Eye-line / Screen Direction (L/R/C)
```

有意越轴必须写动机和重建空间关系的镜头；自由文本“轴线成立”不能代替结构化证据。

每个 ESSENTIAL Beat 还要有 `Recovery Plan`：邻镜替代、hold、crop、cutaway、deterministic layer、重路由，
或明确写 `NONE` 并把它标为生成关键路径。最小 Coverage 不等于零剪辑冗余。

## 2.3 六步选择

1. **锁叙事变化**：用一句话写清进入状态、角色可见选择和退出状态。
2. **锁观看位置**：客观观察、角色 POV、过肩、窥视、主镜头或反应位，只选最有信息价值者。
3. **锁空间关系**：人物左右、视线、移动方向、前中后景、入口出口和 180 度轴线。
4. **选景别与角度**：先决定观众需要看环境、关系、动作还是表情，再选 WS/MS/CU 等。
5. **选一个主运动**：固定、推、拉、摇、移、跟、环绕、升降、手持中默认只选一个；最多加一个低强度修饰。
6. **写起止与降级**：写明摄影机从哪里到哪里、何时停、结尾必须留下什么；同时给出更稳定的替代方案。

## 2.4 叙事功能到镜头策略

| 主要功能 | 默认起点 | 优先策略 | 常见误用 |
|---|---|---|---|
| 定位空间 | WS/高位或眼平主镜头 | 固定、缓慢横移或升降，建立入口出口 | 环绕主体却看不清空间 |
| 发现线索 | MS→CU 或焦点转移 | 轻推、视线匹配、插入镜头 | 快速变焦替代人物发现过程 |
| 人物决定 | MS/MCU | 稳定机位或克制轻推，保留动作前后 | 甩镜、粒子和大幅环绕抢走选择 |
| 危险逼近 | 有明确距离关系的 WS/MS | 缓慢推进、受限手持、前景遮挡 | 无空间锚点的随机抖动 |
| 权力增强 | 略低机位、构图上占优 | 低位轻推或稳定仰角 | 极端广角导致角色变形 |
| 脆弱/孤立 | 环境占比高的 WS 或高机位 | 固定或缓慢拉远 | 把高机位机械等同“弱小” |
| 关系变化 | Two-shot/OTS/反应镜头 | 视线匹配、动作匹配、焦点切换 | 无理由越轴或两人位置互换 |
| 揭示新世界 | 受控遮挡前的近景→环境远景 | 穿过前景、抬升或拉远揭示 | 同时旋转、变焦、加速和变形 |
| 场景转接 | 前后镜共享动作、形状、方向或声音 | 匹配剪辑、遮挡切、J/L Cut | 只写“无缝转场”而无匹配对象 |
| 悬念收尾 | 明确未解决阻碍 | 停住、拉远或把焦点留在后果 | 继续展示角色，漏掉钩子对象 |

情绪是结果，不是自动运镜映射。忧郁不必慢推，紧张不必抖动，梦幻不必旋转。先证明这种
摄影变化让具体人物处境更清楚，再使用情绪修饰。

## 2.5 9:16 竖屏约束

- 主体优先落在中轴附近的上中部安全区，但不要让所有角色垂直堆叠成海报。
- 横向平移空间较短；若横移承担发现关系，必须用前景、中景或视线方向建立可读层次。
- 远景中人物容易过小，必须确认手机尺寸首次观看仍能识别动作和方向。
- 高低关系、纵深通道、门框、瀑布、树干和光束适合竖屏；它们必须属于场景，不得以观察线、
  运动线、空间轴或控制格栅的形式进入生产首帧。
- 转场前后保持主体屏幕位置、动作方向或遮挡物至少一项可匹配；“每段都好看”不等于可衔接。

## 2.6 关键空间关系与参考覆盖

对观众必须回认的地点、对象或行动关系，记录：`本镜必须认出什么 → 哪个实际参考/前镜支持 → 缺证或矛盾 → 处置`。
场域世界关系与屏幕左右分开；反打、变焦或特写不因锚点少、左右变化、新区域多就自动失败。
只查本镜相关关系：眼部特写可不承担全场定位，但仍可能需要身份与眼线；脚部特写可能必须看清脚与边界。

- 无关未知：记录或略过，不增加审批。
- 锁定关键关系缺证：补参考、调整覆盖，或在已有授权允许的 POC 范围内试验；未获实验授权不能自行消耗生成预算。
- 已确认的关键输入矛盾：先消解再发生产包，披露不能替代修复。
- 允许创作的未定义区域：按现有授权继续；不要把它误写为已验证的精确几何。

未知、违约与不适用分开记录；`FIELD_UNKNOWN` 等仅为正文描述，不是新增 status 枚举。
生产就绪不得同时声称关键关系未验证与全部硬门通过。需要改路线时说明叙事保留、参考支持、成本及音频接缝；
拆分、接尾帧或同源视图都不自动保证场域一致，不预设未经标定的数值门槛。

## 2.7 因果剪辑与整集体验

生成单位不是戏剧单位。先组织整段的期待、压力、选择、局部回报与余波，再分配 Shot 和 Segment；
不要把多镜头 POC 的切点数量、固定景别套餐或测试优先级直接继承为正片目标。

剪短前做删除测试：删去后，观众是否仍知道人物如何到达、看见什么、为何改变行动，以及变化的后果？
行走、停顿或反应若承担这些信息，不因“动作少”自动删除。优先去除重复部分；需要插入镜头时，
明确其所属地点、观察者和前后状态。交叉溶解不能补造空间，声音桥也不能替代必须看见的原因。

在 Edit Map 中补记相邻段的 `切出动作/视线 → 下一镜首个信息 → 空间或声音承接 → 不可删信息`。
每个新段不仅单独看，还须与可用邻段按正常速度连看；邻段未返回时标明接口未实证，不冒称衔接已通过。

奇观与节奏按观众体验设计：展示值得关心的状态，再用可见变化使它获得或失去意义。
美景可承担向往和情绪回报，不必每镜发生危险；污染、威胁或失衡也不能只靠调暗画面或旁白命名。
景别、观看距离、表演停顿、运动速度与声音密度共同形成张弛，禁止用更多切镜、更响音乐或更多特效代替。

# 3. 镜头语言选择器

## 3.1 基础摄影词的精确定义

| 术语 | 可执行定义 | 不要混淆 |
|---|---|---|
| Static / Locked | 摄影机位置与朝向固定 | 不是“固定机位同时明显手持抖动” |
| Pan | 摄影机原地水平旋转 | 不是横向平移；后者用 Truck/Slide |
| Tilt | 摄影机原地垂直旋转 | 不是机身升降；后者用 Pedestal/Crane |
| Dolly in/out | 摄影机沿景深方向靠近或远离主体 | 不是改变焦距的 Zoom |
| Truck/Slide | 摄影机横向平移 | 需说明向画面左/右或沿主体哪一侧 |
| Tracking/Follow | 摄影机随主体路径移动 | 必须说明跟在前、侧、后及保持距离 |
| Orbit/Arc | 摄影机沿弧线绕主体移动 | 默认小弧度；360° 是高风险特例 |
| Pedestal/Crane/Jib | 摄影机垂直或弧形升降 | 必须写揭示对象和结束高度 |
| Roll | 摄影机绕镜头轴旋转 | 只在失衡有叙事理由时使用 |
| Handheld | 有边界的手持微动 | 不是随机剧烈抖动 |
| Steadicam/Gimbal | 稳定移动并保持主体构图 | 不等于无物理路径的漂浮 |
| Zoom | 改变焦距与视野，机位不动 | 与 Dolly 组合才构成 Dolly Zoom |
| Rack Focus | 在两个已存在的景深层之间转移焦点 | 不是凭空生成第二主体 |

连续剪辑的 30 度经验规则是：对同一主体的相邻镜头若无明显景别变化，机位角度通常应改变
约 30 度或更多，以免形成意外跳切；不是“两个镜头夹角不得超过 30 度”。180 度规则用于维护
角色左右与视线连续性。两者都是服务空间可读性的剪辑规则，不是无条件公式。

## 3.2 景别、角度与观看关系

| 观众要读什么 | 优先景别/视角 | 需要保留 |
|---|---|---|
| 地点与距离 | WS/ELS、主镜头、鸟瞰或高位 | 人物与出口/阻碍的空间比例 |
| 两人关系 | Two-shot、OTS、反打 | 视线、屏幕方向和权力位置 |
| 可见行动 | MS/MLS | 手、道具、脚步与环境边界 |
| 表情或决定 | MCU/CU | 眼神、呼吸与动作起势 |
| 证据细节 | Insert/ECU/微距 | 细节与主场景的明确归属 |
| 主观体验 | POV、受控窥视或倒影 | 谁在看、看见什么、为何此刻看 |

鱼眼、荷兰角、镜像、隧道、分屏、极端顶视等是高标记性语言。一次使用就会成为观众重点，
因此必须绑定梦境、失衡、监视、困住、分裂或空间揭示等具体理由。

## 3.3 运动速度与结束方式

用可观察词替代伪技术参数：

```text
速度：极慢 / 缓慢 / 中速 / 快速
加速度：匀速 / 轻缓起步后稳定 / 末段减速停住 / 突然启动后立即刹停
稳定性：锁定 / 稳定器 / 克制手持 / 剧烈手持
构图保持：主体居中 / 保持三分位 / 让主体从右三分位移到中轴
结束：停在反应 / 停在证据 / 停在阻碍 / 被前景完全遮挡后切换
```

只有实际工具可控制帧率、快门、焦距或速度曲线时才写精确数值；否则数值会制造虚假控制感。

# 4. 摄影、剪辑与特效的边界

## 4.1 剪辑选择器

| 方法 | 连接依据 | 验收问题 |
|---|---|---|
| Match on Action | 同一动作跨镜延续 | 动作方向、速度和接触点是否一致？ |
| Match Position/Shape | 主体屏幕位置或形状相似 | 切换后观众是否立刻知道看哪里？ |
| J Cut | 下一场声音先进入 | 声音是否真实触发注意或场景变化？ |
| L Cut | 前场声音延续到下一画面 | 延续是否增加因果或情绪，而非拖沓？ |
| Occlusion Cut | 前景完整遮挡画面时切换 | 前后遮挡方向、速度和亮度是否可接？ |
| Cutaway/Insert | 暂离主动作展示信息或反应 | 回到主动作时状态是否连续？ |
| Cross-cut | 两条同时进行的行动交替 | 两线是否互相加压并在时间上可对应？ |
| Dissolve/Fade/Wipe | 时间、空间或风格化段落转换 | 是否有明确语义，而非掩盖断裂？ |

## 4.2 高风险组合

默认避免：

- 同时快速推近、360° 环绕、轴向翻滚与焦距突变；
- 微距细节同时要求大范围追踪或地点揭示；
- 固定镜头同时要求明显手持和大幅重构；
- 一镜中连续完成多人走位、手部交接、长对白、场景变换和角色变身；
- 用视觉特效词替代未设计的遮挡、动作或声音转场；
- 要求“无缝”却不写前后共享的动作、位置、形状、方向或声音。

复杂镜头只有在每一段都有起止状态、过渡触发和失败降级时才允许进入有限试产。

# 5. AI 视频执行语法

## 5.1 生成路由

| Route | 使用条件 | 默认策略 |
|---|---|---|
| `SINGLE_SHOT` | 一个 Shot，连续动作或情绪停留比切镜重要 | 一次 Segment 一个 Shot；时间段只描述动作阶段 |
| `NATIVE_MULTI_SHOT` | 当前平台入口有可定位的相近多镜头执行记录，或本次明确标为 POC | Segment 内列 Shot 顺序，关键切点逐条验收 |
| `INDEPENDENT_SHOTS` | 需要精准构图、独立重拍或确定性剪辑 | 每个 Shot 独立生成，后期硬切或匹配剪辑 |
| `CHAINED_SHOT` | 同一动作超过时长且前后必须连续 | 用上一段真实尾帧或视频作下一段参考，不假设接缝自动消失 |
| `DETERMINISTIC_LAYER` | 字幕、UI、观察标记、魔法几何或模型不稳定元素 | 退出视频生成，在后期分层合成 |

`NATIVE_MULTI_SHOT` 的入口证据至少记录：平台入口、模型标签、日期、时长/画幅/音频、参考输入、
预注册 Shot/关键切点数量、实际可辨认 Shot/切点、失败项和原始输出路径。一条成功样本只证明可行性，
不证明稳定率。没有相近执行证据时默认 `INDEPENDENT_SHOTS`；若仍要测试，必须明确标为 POC、声明预算与停止条件。

### 单动作镜头

适合短镜头或高连续性任务：

```text
叙事功能 + 主体身份 + 单一可见动作 + 空间关系
+ 景别/角度 + 摄影机物理路径 + 速度/停止方式
+ 起始状态 + 结束状态 + 连续性/安全硬约束
```

### 分段连续镜头

仅当实际模型、时长与参考输入已证实支持时使用：

```text
全片共同不变量
0–Xs：进入状态、主体动作、摄影路径、结束锚点
X–Ys：由可见动作/声音/遮挡触发下一段，不瞬移
Y–Zs：完成后果或钩子，摄影机停在必须读到的对象
```

时间码是节奏边界，不是保证。生成前必须另写无时间码的因果摘要，确保模型即使偏离秒点，仍知道
事件顺序。不得因为模型支持长时长，就把多个孤立镜头拼成没有连接动机的“长片段”。

## 5.2 Prompt 顺序

下列是导演字段的逻辑核对顺序，不要求所有路线使用同一排版。原生多镜头完整执行文本采用
`references/ai-production-handoff.md` §7.2.1 的全局、风格、节奏、场景、灯光、角色、逐图与逐镜组织；
同场参考组先按该参考 §6.5 核查。已有用户认可的结构须保留功能，不能为“简洁”删掉说话人或图片职责。
下列“降级”留在导演/执行卡，不与当前方案一起交模型选择。

```md
1. 格式：画幅、时长、连续镜头或剪辑结构
2. 叙事结果：本镜必须让观众理解的变化
3. 主体与参考角色：谁是主要、谁只维持身份
4. 起始空间：前中后景、左右、距离、入口出口
5. 可见动作：按因果顺序，只写屏幕可见行为
6. 摄影：景别、角度、物理路径、速度、构图保持、停止点
7. 转场触发：动作、遮挡、声音、焦点或环境变化
8. 结束状态：下一镜或结尾必须继承什么
9. 硬约束：身份、比例、数量、空间、安全、文字和品牌
10. 降级：复杂运动失败时保留哪一个叙事结果
```

参考图必须按功能标注：`角色身份`、`场景空间`、`起始构图`、`结束状态` 或 `材质/风格`。
不要把观察线、运动箭头、空间轴、格栅、几何占位和说明文字作为生产首帧；需要控制时，用文本、
独立导演图或后期图层表达，不把控制标记伪装成场景资产。

## 5.3 模型可执行表述

差：

```text
史诗、梦幻、电影感、夸张修辞式环绕、焦点爆破、伪微观细节、无缝转场。
```

好：

```text
摄影机从吉米右后方的眼平中景开始，以缓慢稳定器速度跟随他向前两步；
当蓝色反光掠过画面左侧水幕时，摄影机小幅向左平移，让海龟影子进入中景；
吉米在观察边界前停住，摄影机减速并停在能同时看见鞋尖、边界和远处海龟的位置。
```

后者可验证：起点、路径、触发、速度、构图和终点都可从成片检查。

# 7. 对抗式审查与停止条件

安全、权利、严重身份错误与不可播放技术错误属于不可抵消硬门。其余审查顺序为：

```text
上下文隔离观众能否看懂
> 可剪性与空间连续性
> 技术质量
> 风格微差
```

成片至少保留一份上下文隔离回答：审查者观看前不得读取 Director Sequence Card、Camera Direction Card、
Prompt、预期答案或失败归因；记录审查者类型、原始回答和时间。独立模型只能作为辅助证据，
用户指定的最终决策人保留最终审美和生产裁决。
同时记录该审查者实际可见的材料范围及回答保存位置；没有隔离条件就如实写知情自审、尚缺首次观看证据，
不得用身份名称、空 blind 目录或改写后的答案宣称盲评。知情作者可做后续技术复核，但须与原始观众回答分开。
逐属性可观察性及归因按 `references/ai-production-handoff.md` §11.3；单镜 PASS、格式正确和工程测试全绿
均不能替代完整序列审查。新规则不追溯抹去旧接受事件，新增证据应注明适用范围。
已被项目选为主要体验的环境动态、声音身份和视觉回报，须在正常播放中检查，不能一律归为风格微差。
静态美图不能证明动态成立；轻微、无叙事影响的光斑或纹理变化也不应被反向升级成逐帧硬门。

以下任一属于叙事或可剪硬失败：

- 观众无法判断人物在哪里、为何行动或为何进入新场景；
- 角色、信息或空间无因果地突然出现或跳转；
- ESSENTIAL 刺激存在但缺少必要反应或可见后果；
- 持续镜头未执行批准的 Timed Attention Path；
- `DIRECTOR_CRITICAL` 切点缺失且不能由现有画面确定性补救；
- 轴线、方向或空间重构使观众误解行动。

## 7.1 四方攻击

| 审查者 | 必问问题 |
|---|---|
| 怀疑观众 | 第一次看能否说出为什么移动、为什么转场、最后发生了什么？ |
| 逻辑检察官 | 运镜是否保持事件顺序、空间轴、视线和动作因果？ |
| 人物辩护人 | 摄影是否看见人物的选择，还是只展示模型奇观？ |
| 制作与风险制片人 | 当前模型能否执行；失败时是否保留安全、身份和叙事结果？ |

## 7.2 Finding 最小结构

每条镜头导演 Finding 仍须包含：证据位置、失败机制、下游影响、最小修复、验证方法、负责人和状态。
“镜头不够高级”“增加电影感”“再丝滑一点”不是可执行 Finding。

## 7.3 有限停止

- 先验收叙事硬门，再看风格微差；硬门通过后，不因不改变身份、因果、安全或可剪性的轻微漂移重抽。
- 每次生成前核对当前委托、允许的尝试与实际消耗；余额不等于重试授权，无效或不可评样本也计入消耗。
- 同一失败连续出现两次，优先改镜头设计、关键帧、资产或生成策略，不继续堆否定词。
- 若唯一修复需要改变人物选择、场景因果或锁定资产，停止并回到上游 Notice，不在 Prompt 中静默改写。
- 单次成功只能证明该样本可行；不得升级为模型稳定能力或通用导演规律。

## 7.4 来源与权利边界

本参考的来源、许可和拒绝项记录在 `references/DIRECTOR-MODULE-SOURCE-AUDIT_v0.1.md`。用户提供的内部
镜头词表与两份 `CameraStyles` 片段只作为纠错语料；重复内容、异常标签、伪技术参数、作品/作者式风格
指代和错误定义均未继承。第三方方法只在许可明确的边界内做独立重述；Mx-Shell、未许可社区 Prompt
与可识别近似表达不得进入本参考。公开分发原始词表或第三方独特表述前必须另行确认权利、来源与许可。

## 7.5 使用反馈转为规则的边界自查

以下为制作反馈抽象后的知情自查例，不是独立盲评、模型稳定率或创作改善的实测结论。

| 情境 | 应改变的决策 | 反例 / 不应扩张为 |
|---|---|---|
| 剪掉步行后角色突然到达另一位置 | 保留必要移动或用有空间归属的发现/反应覆盖连接 | 所有走路必须完整保留 |
| 流水背景在视频中像静止贴图 | 核对动态要求、实际参考和运动表现；再决定修哪一层 | 每个背景必须运动、加满粒子 |
| 同一叙述者跨段换声 | 在生成前分配旁白与原生音频职责并绑定声音身份 | 所有项目必须女声或必须后期配音 |
| 已有保护效果跨镜无故消失 | 记录建立、延续、消退条件，并区分出画与消失 | 所有人物都需要保护效果 |
| 威胁只剩调暗滤镜 | 展示它改变的通路、生态或人物选择；来源未证则不伪装已知 | 一律加怪物、血腥或大声惊吓 |
| 几个合格单段拼起来平淡 | 回查情绪回报、信息递进与相邻段接口 | 固定每秒切镜或重复抽取同一测试 |
| 图数和镜头变多后整集获得正面反馈 | 保存完整制作组合、输入映射与反馈范围，后续按同类任务复用 | 证明某个图数单独致效、要求所有段同样镜数 |
| 台词文本正确但说话人错位 | 核对实际 Prompt 中逐镜归属、参考表演与成片声音，不先归咎操作者 | 一句“不得念错”能保证声画绑定 |
| 两张图描述同物先后状态，回片却出现两件 | 检查时间状态、数量约束和连续动作的实际可读性 | 每张静图正确即整段连续性通过 |
