# 歌曲 MV：从原曲到可继续编辑的交付

这是恢复任务的路由，不是另一份项目基线。仅在完整 MV、全流程复盘或编辑器迁移时使用；
明确的单镜返修只进入受影响环节，不重开整片，也不强迫新建所有表格。

## 先找最早失效环节

MV 的有效单位是原曲中一段可被观看的变化：音乐提供时间，表演和意象赋予时间以意义。
静态美图、可播放文件、同步歌曲和可编辑工程分别解决不同问题，不能相互代验。
从当前 Manifest 恢复用户决定、素材接受范围与剩余问题，按下表读取需要的规则。

| 当前环节 | 实际要检查的产物 | 进入下一环节的依据 | 规则位置 |
|---|---|---|---|
| 整曲设计 | 原曲下的时间条预演、期待—变化—回报、重复段比较 | 听审并做删除/调序检查；目的句齐全不算通过，核心冗余先重写再生图 | [导演 §2.8](cinematography-director.md#28-歌曲-mv整曲推进与母题变奏) |
| 场域与人物 | 实际母版、适用派生视图、原角色、生图正文和逐张出图记录 | 生成前实际输入相容；出图后人物、场景、入景关系及邻镜分别质检 | 交接参考 §6.4–6.7；导演 §2.6 |
| 生成输入 | 实际上传图和音频、唯一 Prompt、已知平台设置 | 职责明确；累计纠正保留；已有关键冲突已排除 | 交接参考 §7.2.1；模板 §2.1 |
| 回片 | 原文件、原尺寸画面、原速动作与实际声音 | 分别核查身份/焦点/动作/演唱；采用范围有依据 | 交接参考 §11.3；演唱用 §7.2.2 |
| 试剪与成片 | 连同原曲播放的相邻镜及整曲、可编辑字幕 | 嘴部与歌字、进出动作、情绪推进、字幕均检查；技术检查单列 | 交接参考 §7.2.2；导演 §2.7–2.8 |
| 高清与接力 | 短样片、目标软件中的工程及试导出 | 源细节与增强结果分开；实际打开并播放受影响窗口 | 交接参考 §11.3、§7.2.3；模板 §2.2 |

“未检查”不是“不通过”，也不是“通过”。用户已接受的素材继续保留；新发现只重开受影响关系。
详细规范统一在 [AI 制作交接](ai-production-handoff.md) 与 [生产交接模板](../templates/production-handoff.md)，不在此复制。

## 复盘必须追到真实执行物

在项目现有复盘写一行证据链：

`用户观察 → 实际版本/窗口 → 最早失败环节 → 适用规则 → 改过的输入或决策 → 如何验证/尚未验证`

对抗检查至少覆盖以下四种责任，作者自审须明确为自审，不冒称独立观众测试：

- 观众：移开分镜解释，原曲下的连续画面是否仍能看出变化、期待和情绪回报？
- 连续性：所谓一致是否真实保持空间与身份，还是用相同姿态掩盖缺少覆盖？
- 表演：人物在对谁唱、试图得到什么、如何受挫？眼线、呼吸与身体反应是否在景别内可见？
- 制作：用户将复制和上传的究竟是哪份文件？失败会不会再次收费？目标编辑器里是否真能播放与修改？

反向检验：更短不必然更好；更多镜头不必然更有节奏；更长 Prompt 不必然更可控；
更高分辨率不修复错误身份、失焦或口型；多写规则不能替代实际输入检查。

沿用已验证的组合与适用条件，不把某项目的镜数、画幅、灯具数量、字体或模型名字升为通用要求。
一项反馈已有规则覆盖时，优先修实际入口、模板使用或执行物，而不是再追加同义禁令。
本地 Skill 更新、文字复验、媒体回片成功、整片接受、Git 提交和远端推送分开报告。
