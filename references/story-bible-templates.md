# 故事圣经模板与连续性系统

> 本文件是 `professional-screenwriter` 的按需参考资料。
>
> 当任务涉及电影、剧集、季播剧、连续短剧、系列世界观、人物资料、分集规划、多人协作、剧本续写、版本管理、连续性审查或对外 Pitch 时加载。
>
> 主 `SKILL.md` 的第一性原理、因果、人物主动性、对抗式审查、安全、版权和内容边界优先。
>
> 本文件不负责把故事“写得好看”；它负责把已经成立的故事事实、选择、规则、状态与版本变更记录为可检索、可协作、可审计的系统。
>
> 核心目标：
>
> ```text
> 不让设定只存在于作者脑中；
> 不让人物、时间、道具和信息在后续创作中悄悄矛盾；
> 不让对外 Pitch 与内部制作使用两套互相冲突的故事。
> ```

# 1. 第一性原理

## 1.1 故事圣经不是设定百科

失败的故事圣经常见形式：

```text
大量世界观历史
大量人物出生年月
大量机构、城市、制度、家族谱
大量作者知道但剧情永远不会调用的信息
```

这些内容不自动构成故事能力。

有效的故事圣经只记录会影响以下问题的事实：

```text
谁能做什么？
谁知道什么？
谁想要什么？
谁欠谁什么？
什么规则限制行动？
什么事件已经发生？
什么后果尚未结算？
下一次选择为什么会不同？
```

若一项资料无法影响人物选择、冲突、信息、制作或连续性，则不应优先进入主圣经。

---

## 1.2 圣经是“状态机”，不是静态文档

故事中每个重要元素都具有状态：

```text
人物关系：陌生 → 合作 → 怀疑 → 背叛 → 决裂
道具：在抽屉 → 被主角取得 → 被对手复制 → 证据失效
秘密：无人知晓 → 主角知晓 → 观众知晓 → 对手知晓 → 公开
伤病：无伤 → 右手擦伤 → 包扎 → 感染/痊愈
世界规则：可用 → 代价显现 → 被突破 → 规则重定义
```

故事圣经必须记录状态变化，而不是只记录“人物简介”。

---

## 1.3 单一事实源

任何项目必须有一个被定义为“剧情事实源”的文件或目录。

原则：

```text
没有记录的设定，不自动视为事实。
已被新版本明确推翻的设定，不再是事实。
不同文件冲突时，以锁定版本和版本日志为准。
```

禁止：

```text
剧本说角色已经知道秘密；
人物小传说角色还不知道；
分集表说秘密下一集才揭示；
分镜中却把角色拍成已知状态。
```

# 2. 圣经类型

## 2.1 内部活圣经

适用：

- 编剧室
- 多人协作
- 连续短剧
- 多集剧集
- AI 视频批量生产
- 长期项目开发

特点：

- 持续更新
- 包含剧透
- 记录版本、矛盾和待决项
- 可包含预算、资产与制作约束
- 用于真实生产，不追求视觉包装

## 2.2 对外 Pitch Bible

适用：

- 融资
- 发行
- 平台提案
- 寻找制片或合作方
- 项目介绍

特点：

- 只展示足够证明项目可持续的内容
- 有剧透边界
- 强调概念、人物、世界、首季与未来空间
- 不展示全部内部版本争议、废弃支线和制作问题
- 阅读体验优先，但不能虚构故事能力

## 2.3 角色圣经

适用：

- 人物驱动项目
- 多角色群像
- 长期连续剧
- AI 视频角色一致性
- 演员、配音或表演方向沟通

特点：

- 记录人物目标、信念、关系、声音和状态
- 不止外貌，不止履历
- 重点是人物在压力下如何选择

## 2.4 世界与规则圣经

适用：

- 科幻
- 奇幻
- 悬疑
- 历史
- 行业剧
- 复杂机构或系统故事

特点：

- 只保留会影响剧情因果的规则
- 每项能力、制度或异常机制必须有边界、成本和漏洞
- 明确角色掌握规则的程度

## 2.5 生产连续性圣经

适用：

- 实拍项目
- AI 视频项目
- 多导演、多编剧、多剪辑项目
- 长期短剧生产

特点：

- 重点记录场景、服装、伤病、道具、镜头、资产和时间
- 与剧本事实源双向关联
- 不替代故事圣经，但必须与其同步

# 19. Story Bible 对抗式审查

## 19.1 事实源红队

质疑：

- 哪些关键信息只存在于作者脑中？
- 哪些文件对同一事实给出不同答案？
- 哪些“设定”从未影响剧情？
- 哪些重要状态变化没有记录？
- 是否存在两套不同版本被同时使用？

## 19.2 人物红队

质疑：

- 每个主要人物是否有不可替代功能？
- 是否存在角色只用于送信息、制造误会或被拯救？
- 人物目标、恐惧、资源和策略是否记录完整？
- 人物状态是否与剧本中实际行动一致？
- 关系变化是否有事件支撑？

## 19.3 因果红队

质疑：

- 因果脊柱中是否有“然后”而不是“因此/但是”？
- 是否存在资源、规则、技能或证据凭空出现？
- 每个重大转折是否有前文条件？
- 结局是否由圣经中的人物与规则真正支持？
- 是否有不记录就会导致后续矛盾的秘密或道具？

## 19.4 信息红队

质疑：

- 谁在何时知道什么？
- 是否有人知道不应知道的信息？
- 是否有人忘记已知信息？
- 哪些秘密被拖延却没有合理原因？
- 观众、主角、对手的知识差是否被清楚设计？

## 19.5 生产红队

质疑：

- 圣经中的角色、地点、道具、服装是否超过制作能力？
- 新增资产是否每次都服务剧情？
- AI 视频是否能维持现有角色与场景数量？
- 是否存在真实人物、品牌、地点、声音、版权和敏感内容风险？
- 是否存在可在不伤害因果的前提下合并或降级的资产？

# 20. 圣经质量评分

每项 0–5 分，必须附证据。

| 维度 | 核心问题 |
|---|---|
| 事实清晰度 | 核心设定是否可快速查到？ |
| 单一事实源 | 是否有明确优先级和版本规则？ |
| 因果可追溯性 | 能否从事件追到选择和后果？ |
| 人物可执行性 | 人物目标、恐惧、策略、弧是否清楚？ |
| 信息管理 | 谁知道什么是否可追踪？ |
| 时间连续性 | 时间、移动、伤病、倒计时是否一致？ |
| 关系动态 | 关系是否有状态与转折记录？ |
| 规则边界 | 世界规则是否有成本、限制和漏洞？ |
| 伏笔回收 | 埋设、部分回收和完整回收是否可追踪？ |
| 制作可用性 | 资产、服装、道具和场景是否可交接？ |
| 版本纪律 | 变更是否被记录并触发复审？ |
| 低噪声 | 是否只保留影响剧情和制作的必要信息？ |

评分解释：

```text
0：不存在或严重矛盾
1：有碎片信息，无法作为协作依据
2：可用但缺少关键状态、版本或连续性
3：基本完整，局部检索和更新困难
4：清晰、可协作、可审计
5：低噪声、可追溯、与剧本/制作实时同步
```

# 23. 最终原则

故事圣经的价值不在于记录得多，而在于让正确的人在正确时间找到正确事实，并据此做出一致的创作和制作决定。

始终优先记录：

```text
会改变选择的事实；
会产生后果的规则；
会造成矛盾的时间与信息；
会影响制作的角色、道具、服装和场景；
会决定结局是否成立的伏笔与代价。
```

不要把它写成设定展览。

把它维护成：

```text
故事的单一事实源
+ 人物状态机
+ 因果审计表
+ 连续性控制台
+ 制作交接基础设施
```
