# 上游变更通知与下游同步日志

> 本文件是 Notice 索引与模板说明；单次变更应创建独立的 `NOTICE-*` 文件。
> 全局字段、状态和门禁服从 `control-plane-contract.md`。

> 文件名建议：
>
> ```text
> NOTICE_[[项目缩写]]_[[通知编号]]_[[简述]].md
> ```
>
> 示例：
>
> ```text
> NOTICE_TIDELINE_NOTICE-014_顾川提前得知签名.md
> ```
>
> 归档索引建议：
>
> ```text
> /notices/
>   README.md
>   NOTICE_[[PROJECT]]_NOTICE-001_[[slug]].md
>   NOTICE_[[PROJECT]]_NOTICE-002_[[slug]].md
> ```
>
> 本文件适用于：
>
> - 故事事实变更；
> - 角色、关系、世界规则、时间线、道具、伤病、信息状态变更；
> - 分集重排、场景删除、高潮重写；
> - 台词或镜头中改变已锁定事实的修改；
> - AI 资产、制作交接、分镜、声音、UI、后期文件的同步；
> - 已锁稿后需要受控修改的项目。
>
> 本文件不是普通更新日志。
>
> 它必须回答：
>
> ```text
> 什么上游事实改变了？
> 旧事实是什么？新事实是什么？
> 为什么必须改？
> 哪些下游文件、场景、资产、决策和承诺依赖这个事实？
> 每项依赖是否已更新、复验、批准？
> 若变更失败或引入矛盾，如何回退？
> ```

# 0. 核心模型

## 定义

```text
上游（Upstream）：
被其他文件、场景、资产、制作决策或故事事实依赖的来源。

下游（Downstream）：
依赖上游事实，并在上游变化时可能变得错误、过期、
自相矛盾、不可制作或无法兑现的内容。

变更通知（Notice）：
一次受控传播事件的记录，不等于“我改过了”。
```

## 依赖方向

```text
项目意图 / 用户约束
        ↓
Story Bible（事实源）
        ↓
季结构 / 长片大纲 / 分集目录
        ↓
场景卡 / 分集大纲
        ↓
剧本主源
        ↓
对白、动作、镜头、分镜、资产、制作包
        ↓
拍摄 / AI 生成 / 后期 / 字幕 / 音频 / 发布
```

> 依赖通常向下传播，但实际发现问题可以向上追溯。
>
> 例如：
>
> ```text
> 分镜发现“顾岚右手旧伤”消失
> → 回查剧本
> → 回查场景卡
> → 回查 Story Bible 的伤病状态
> → 修复事实源后再重新下发。
> ```

## 不可违背原则

```text
1. 不得只修改一个下游文件，然后假定其他文件会自然同步。

2. 不得用“最新版在我脑中”替代已写入的事实源。

3. 不得因为已经制作或已经写完，而保留明显失效的因果。

4. 不得把“更新了措辞”误报为“未改变故事事实”。

5. 不得在未列出受影响依赖前锁定重大变更。

6. 不得让某个下游资产成为新的事实源，
   除非该资产被正式提升并记录版本。

7. 任何涉及主角目标、对手身份、世界规则、高潮、结局、
   关键秘密、人物伤亡、关系状态或关键道具的变化，
   都必须触发对抗式审查。
```

# 5. 变更等级与门禁

## L1：文字或表达级

```text
定义：
不改变故事事实、人物知识、因果、资产状态或制作要求。

例：
- 修正错字；
- 统一角色名称；
- 在不改变含义下压缩台词；
- 调整非关键动作描述。
```

最小门禁：

- [ ] 确认不改变事实
- [ ] 检查角色声音与语调
- [ ] 更新受影响文件版本号
- [ ] 记录变更摘要

## L2：局部剧情级

```text
定义：
改变局部场景、道具、信息披露、关系温度、动作顺序或资产状态，
但不改变核心故事发动机与结局逻辑。

例：
- 关键道具从 A 转交给 B；
- 某秘密提前一集揭示；
- 角色在第 6 场受伤而非第 7 场；
- 两场合并；
- 次要地点被替换。
```

最小门禁：

- [ ] 更新 Story Bible 中对应状态
- [ ] 更新场景卡与剧本
- [ ] 更新信息矩阵、道具/伤病/服装、时间线
- [ ] 复验相邻场景接口
- [ ] 复验资产与制作包

## L3：结构级

```text
定义：
改变主角目标、对手策略、关键关系、中点、危机、高潮、
关键秘密、世界规则或季级问题。

例：
- 主角从“证明清白”改为“救妹妹”；
- 对手身份改变；
- 中点真相改变；
- 高潮不再由主角做选择；
- 核心世界规则改写；
- 主角与关键人物关系翻转。
```

最小门禁：

- [ ] 完整更新 Story Bible
- [ ] 重建因果脊柱
- [ ] 复审人物弧与关系矩阵
- [ ] 重建信息矩阵、谜团回收与时间线
- [ ] 复审全部受影响大纲、场景卡、剧本
- [ ] 复审全部资产、分镜与制作交接
- [ ] 执行对抗式审查
- [ ] 审批后方可锁定

## L4：项目级

```text
定义：
改变格式、受众、商业模型、制作模式、总时长、平台边界、
主类型或项目核心承诺。

例：
- 长片改为 36 集竖屏微短剧；
- 9:16 改为横屏院线长片；
- 从实拍改为 AI 生成；
- 免费内容改为解锁付费；
- 悬疑剧改为家庭喜剧。
```

最小门禁：

- [ ] 重新确认用户/制片意图
- [ ] 重写项目定义、Logline、格式与受众假设
- [ ] 重新评估故事发动机是否仍成立
- [ ] 重做结构、场景、资产与制作方法
- [ ] 重做风险、权利、安全与预算评估
- [ ] 对既有内容逐项决定保留、重写或废弃
- [ ] 单独生成新基线版本
- [ ] 执行独立对抗审查

# 6. 影响评估

> “受影响”不等于“提到同一角色”。
>
> 只有当文件、场景、资产或决策依赖旧事实时，才构成必须同步的下游依赖。

## 6.1 影响维度

| 维度 | 检查问题 | 影响等级 |
|---|---|---|
| 因果 | 前后事件是否仍能用“因此/但是”连接？ | 无 / 低 / 中 / 高 |
| 目标 | 主角、对手或场景目标是否变化？ | 无 / 低 / 中 / 高 |
| 人物 | 动机、知识、策略、伤病、关系是否变化？ | 无 / 低 / 中 / 高 |
| 信息 | 谁知道什么、何时知道、是否相信是否变化？ | 无 / 低 / 中 / 高 |
| 时间 | 倒计时、移动、昼夜、年龄、事件顺序是否变化？ | 无 / 低 / 中 / 高 |
| 世界规则 | 能力、限制、成本、例外是否变化？ | 无 / 低 / 中 / 高 |
| 谜团 | 伏笔、误导、部分兑现、完整回收是否变化？ | 无 / 低 / 中 / 高 |
| 连续性 | 道具、服装、伤病、地点、空间方向是否变化？ | 无 / 低 / 中 / 高 |
| 制作 | 地点、角色、群演、特技、VFX、AI 资产是否变化？ | 无 / 低 / 中 / 高 |
| 声音/字幕 | 台词、配音、字幕、屏幕文字、UI 是否变化？ | 无 / 低 / 中 / 高 |
| 商业 | 集尾钩子、付费点、兑现窗口、时长是否变化？ | 无 / 低 / 中 / 高 |
| 权利/安全 | 肖像、品牌、敏感内容、平台边界是否变化？ | 无 / 低 / 中 / 高 |

## 6.2 影响结论

```text
总体影响：低 / 中 / 高 / 阻断

本次变更是否会：
- [ ] 改变主角下一步行动
- [ ] 改变对手可用策略
- [ ] 改变观众知道的真相
- [ ] 改变任何人的知识状态
- [ ] 改变世界规则或规则成本
- [ ] 改变中点、危机、高潮或结局
- [ ] 使既有伏笔失效
- [ ] 使任何道具、伤病、服装或时间线失效
- [ ] 使已生成/已拍资产过期
- [ ] 使付费点、集尾钩子或兑现失效
- [ ] 引入新的版权、肖像、安全或合规风险
```

# 11. 对抗式审查

> 任何重大上游变更都要假设：
>
> ```text
> 它解决的问题可能是真的，
> 但它也很可能只是把问题移动到别处。
> ```

## 11.1 事实源红队

- 旧事实是否真的被废弃，还是仍散落在多个文件中？
- 新事实是否只被写进某一份下游剧本？
- 是否存在两个文件对同一角色、道具、时间或秘密给出不同答案？
- 哪个文件有权裁定冲突？
- 是否明确标记旧版本为 `SUPERSEDED`？

## 11.2 因果检察官

- 新事实改变了哪一个人物选择？
- 若没有人物选择改变，这个变更是否只是装饰？
- 新事实是否使前后事件仍能用“因此/但是”连接？
- 是否让某个旧转折失去原因？
- 是否需要新增前置铺垫？
- 是否用新设定遮盖旧因果漏洞？
- 新高潮是否仍来自主角选择，而非巧合、外援或临时规则？

## 11.3 人物辩护人

- 角色知道新事实后，最合理的行动是什么？
- 剧本是否仍让角色按旧知识状态行动？
- 哪个角色会最强烈反对新事实，为什么？
- 新版本是否让人物更像作者工具？
- 是否需要重新审查目标、恐惧、资源、限制和策略？
- 关系权力变化是否被实际行为支撑？

## 11.4 信息审计员

- 谁在什么时刻知道什么？
- 观众知道得更多、相同还是更少？
- 新揭示是否改变行动，还是只增加说明？
- 旧伏笔是否变成死线索？
- 是否出现“人物忘记已知信息”？
- 是否存在为了保留悬念而不合理的沉默？
- 钩子是否仍会被下一集/下一场兑现？

## 11.5 连续性监督

- 人物在哪里？
- 现在是何时？
- 他们穿什么、带着什么、伤在哪里？
- 道具目前属于谁？
- 角色的手机、钥匙、武器、证件、文件是否可用？
- 空间方向、门窗、左右位置是否变化？
- 时间、天气、光线、伤病恢复是否仍连续？

## 11.6 制片与风险负责人

- 此变更是否增加地点、角色、群演、服装、动作、VFX、后期或生成难度？
- 是否可在不破坏因果的前提下降级？
- 已拍/已生成镜头是否仍可使用？
- 是否让 AI 资产需要重新建立角色或地点锚点？
- 是否引入可读小字、复杂手部交接、长口型、群像或长动作？
- 是否出现新的肖像、版权、商标、敏感内容或安全风险？
- 是否需法务、平台、医疗、法律、行业或文化顾问确认？

## 11.7 反事实测试

```text
假设新事实不存在：

- 旧版是否真的无法成立？
- 是否存在更小、更便宜、更少连锁反应的修复？

假设新事实完全成立：

- 哪个角色的合理行为会立即不同？
- 哪个旧场景将不再成立？
- 哪个未来承诺必须被重写？
- 哪个已锁资产会立即变成错误？
```

# 16. 最终原则

```text
上游变更不是一次编辑动作。

它是一次因果、人物、信息、连续性和制作依赖的重新协商。

真正完成的标准不是：
“新版本已经写进去。”

而是：

旧事实不再污染下游；
新事实已在权威来源锁定；
依赖它的每个场景、角色、道具、资产和承诺都已同步；
已知风险被验证、缓解或明确接受；
项目团队能够在同一个版本事实上继续工作。
```
