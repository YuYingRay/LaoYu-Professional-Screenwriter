## 2.1 AI 视频的逐段执行交付

适用于含生成视频的委托。仅需实拍交接时可省略。若项目已有用户认可的等价格式，保留该格式，
不用额外填一套表。正文内容取自当前源稿和实际图片；这部分是管理与核查信息，不整页粘贴给视频模型。
制作中的草案明确缺口，交付执行版本才填入已核实文件与参数。模板占位符不能直接提交。

本次交付单位：[[单镜／整段／整片]]；继承的方法及依据：[[有效决定或制作包]]。
本次改变及理由：[[如实填写或无]]；本轮实际完成与未完成：[[按原委托范围说明]]。

歌曲 MV 的整片/整段重编另在已有镜表中落实（导演参考 §2.8；单镜委托不强制扩成整曲）：
[[原曲窗口与时间闭合]]；[[本镜新揭示的关系/表演或意象变化]]；[[景别/视点/速度及与邻镜的对比]]；
[[已有回片采用范围或缺少的新覆盖]]；[[生成长度≠采用长度、歌句同步位置]]。
在大纲/镜表按音乐段记录[[原曲时间条预演与听审范围、观众期待→可见变化→本段回报→继续观看理由]]；
反复出现的场景/物件/情绪另写[[相较上次的新意义；删除/调序是否有损失；保留/缩短/改写及依据]]。
未解决的核心冗余不直接铺成批量生图任务；留白与音乐复现有依据时可保留。
复盘中要改变的核心问题必须能指向实际镜号、图像或Prompt正文；未知的音频切点/新回片保持未验证，
不能以“电影感、保持一致、微微悲伤”代替动作、剪辑和素材依据。移开此说明后，实际上传与复制正文仍应成立。

### 可复制的完整 Prompt

演唱回填整片时另核对（见交接参考 §7.2.2）：
[[原曲窗口／回片实际歌字时序／校正候选及嘴部验证]]；[[前镜末态→演唱首态→末态→后镜首态的动作与构图证据]]；
[[歌句欲望→可见身体或眼神行动→反应，当前景别能否承载]]；[[生成底片文字约定／后期歌词文本、时间轴和字幕样式]]。
技术检查结果与这四项实际效果分开填写，不用“已到盘”“声音一致”或“渲染通过”替代。

若本次明确为“单张现有分镜图＋原声音频”的演唱单镜重生成，使用交接参考 §7.2.1 的演唱分支：
`原图机位／景别／头部朝向／眼线 → 原唱同步 → 有注视落点的表情与情绪反应 → 眼嘴清晰＋既定字幕／文字输出约束`。时长、上传和剪辑位置留在操作说明；
不重复展开场景和衣饰清单；用户已约定下方章节时保留章节，用必要短句填写，不把这一局部分支用于删结构或缩减整段委托。
精简前后核对累计纠正，不能只保留最近一条。若要求干净演唱画面，可用一句“画面不生成字幕、歌词文字或其他叠加文字”；
用户明确需要文字时按当前字幕方案执行，不把示例当通用禁令。以上必要约束要进入每份实际复制正文，不能只留在说明页。

以下组织方法由执行者展开成当前段落的完整正文，再另存为项目约定的 Prompt 文本。
使用者无需同时复制管理页才能补全角色或图义。逐镜独立生成时，每份 Prompt 展开必要共用条件，
并保留本段剪辑顺序；明确单镜测试只填所需一镜，不强制多镜。章节名可按已认可格式调整。

```text
全局
[[已确认画幅、时长和生成方式；本段可见因果；结束时仍未发生的结果；音频输入职责]]

风格与节奏
[[已认可的材质、表演质感；哪里看清动作、哪里完整说唱、哪里留反应；不把图按等时轮播]]

场景
[[同一空间的前中后景、人物与关键物位置、视线及摄影轴线；当前可见区域]]

灯光与动态环境
[[当前时段的实际光源与受光、环境如何响应动作；只继承相容时段]]

角色与声音
[[身份和服装可见结构、本段欲望及情绪变化；对白／原曲／画外声／环境声如何分工]]

逐图绑定
[[按真实上传顺序逐张写内容、职责、对应镜头和继承边界；同物前后态不复制为两个物件]]

镜头描述
[[逐镜展开：镜号｜设计时间或已核时段｜图号｜景别与机位。
承接起态→可见表演与动作→环境反应；一个主运动及其观看目的。
此镜完整台词／歌句与说唱者，或明确画外／无对白；音效随什么动作发生。
结束状态、切出触发与下一镜承接。按段落重复该结构，不能只给一个示例镜。]]
```

发出前对照实际图组和正文：本段的定位、行动、反应及结果是否按需要被覆盖；声音是否落到正确镜头；
精炼后是否还保留身份、逐图职责和剪辑接口。所有标题填满不代表通过。旧方法的删减及理由在管理页说明，
互斥备选和未确认参数不混进可执行 Prompt。局部测试的输入与结果保持局部用途，不替代整段完成状态。

### 当前正文清单接口（合入项目已有清单，不另建一套状态）

prompt_contract.headings：本项目用户约定的有序标题字符串列表；无此约定时不机械强制下列七节。
inputs：每项含唯一 id、video_prompt_path（相对清单目录或绝对路径）及 status。
execution_allowed：是否允许提交；为 true 时每项状态须为 APPROVED 或 LOCKED，文字写完不能自行升级。
每项只保留一个当前视频正文；生图 Prompt、原回片记录与归档不列作另一份当前视频正文。
网页读取 video_prompt_path 的原文，不再嵌入另一份手写长短版。运行 check_prompt_contract.py 检查实际文件，
再核对正文与图片/声音的语义；机器通过不能放行已知画面矛盾。
