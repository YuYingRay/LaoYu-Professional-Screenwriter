# 竖屏微短剧单集模板

> 文件名建议：
>
> ```text
> VE[[集数]]_[[集名缩写]]_v[[版本]].md
> ```
>
> 示例：
>
> ```text
> VE08_BLACKLIST_v03.md
> ```
>
> ID 与文件名映射：`artifact_id` 等 canonical 字段始终使用 `EP-[[NNN]]`；
> `VE[[集数]]` 只用于竖屏单集的文件名与叙述展示。两者集数必须相同并一一对应，
> 例如 `VE08 ↔ EP-008`；canonical 字段不得写入 `VE*`。
>
> 本模板适用于：
>
> - 9:16 竖屏微短剧
> - 手机优先连续剧情
> - 约 30 秒至 5 分钟的短集
> - 付费解锁、广告支持或自然追更的短剧
> - AI 视频或轻量化实拍的短集交接
>
> 本文件不是“压缩版长剧集大纲”。
>
> 本集必须在有限时长内完成：
>
> ```text
> 人物 + 失衡
> → 明确问题
> → 主动行动
> → 阻碍/反制
> → 状态变化
> → 可兑现的下一集问题
> ```
>
> 主 `SKILL.md` 的安全、人物主动性、因果、版权与对抗式审查规则优先。
>
> 同时读取：
>
> ```text
> short-drama-playbook.md
> hook-paywall-engine.md
> story-bible-templates.md
> ai-production-handoff.md（若涉及 AI 视频制作）
> ```

# 1. 第一性原理

## 1.1 这一集为什么存在

不要用“这一集需要过渡到下一集”作为存在理由。

本集必须至少完成以下一项：

- 主角做出新选择；
- 主角为先前选择付出后果；
- 关系权力发生变化；
- 关键信息改变行动；
- 对手取得或失去优势；
- 资源、身份、时间或安全状态改变；
- 一个旧问题得到局部答案，并产生更高层新问题。

若本集只做以下事情，应合并或重写：

```text
重复回顾
解释设定
重复争吵
重复羞辱
人物走路、打电话、等待
把上一集的钩子延后
用无关支线拖延答案
```

## 1.2 本集最小因果循环

```text
钩住注意
→ 明确当前问题
→ 人物采取行动
→ 行动遭遇阻碍或反制
→ 状态发生变化
→ 新后果形成下一集问题
```

这意味着：

```text
切黑不是钩子。
大声不是冲突。
震惊不是转折。
拖延不是留存。
付费不是对未兑现承诺的许可证。
```

# 4. 竖屏视觉与制作约束

## 4.1 画幅原则

```text
画幅：9:16
观看设备：手机优先
视觉优先级：脸部 > 手部关键动作 > 关键道具 > 可读空间关系 > 环境氛围
```

竖屏不是把横屏画面裁窄。

本集应优先让观众在小屏幕上快速读到：

- 谁是当前主体；
- 人物的情绪和目光方向；
- 关键手部动作；
- 关键道具；
- 两人之间的近距离权力关系；
- 门、手机、合同、戒指、证据、伤口等叙事关键物。

## 4.2 安全区

- 主角脸部与关键动作应处于中上部可读区域。
- 避免让关键人物长期处于画面最下端。
- 屏幕文字、字幕、平台 UI、手势区域可能遮挡下部画面。
- 不将唯一关键信息藏在极小文字中。
- 不依赖远景中的复杂群像来传达情节。
- 对话时优先确保角色脸、眼神、手势或关键道具至少有一项清楚可读。

## 4.3 本集视觉计划

| 项目 | 设定 |
|---|---|
| 主体优先级 | [[谁/什么必须最显眼]] |
| 主景别 | ECU / CU / MCU / MS |
| 空间关系 | [[谁在前景、谁在背景、谁压迫谁]] |
| 关键道具 | [[最多 1–3 个]] |
| 关键动作 | [[一个主要动作]] |
| 光线状态 | [[日/夜；主光逻辑]] |
| 字幕/屏幕文字方案 | 后期字幕 / UI 合成 / 无 |
| 禁止画面 | [[无额外人物、无复杂群像、无乱码 UI 等]] |

## 4.4 AI/实拍降级策略

| 需要呈现的事 | 高风险写法 | 优先替代 |
|---|---|---|
| 大型事故 | 一镜完整呈现灾难 | 声音 + 闪光 + 人物反应 + 后果 |
| 精确手机内容 | 直接生成可读屏幕 | 后期叠加 UI 或字幕 |
| 长对白口型 | 一镜到底完整台词 | 正反打 + 后期配音 + 反应镜头 |
| 复杂打斗 | 多人物连续动作 | 拆局部动作、遮挡、声音和剪辑 |
| 群体骚乱 | 大量可控群众 | 局部人群、声音、剪影、后果 |
| 关键物交接 | 一镜手部精确传递 | 特写关键帧 + 切反应镜头 |

# 6. 本集节拍表

## 节拍 1：入口钩子

### 目的

在最短时间内提供：

```text
人物
+ 即时失衡
+ 具体风险
```

### 填写

- 第一可见画面：
- 当前主体：
- 立即失衡：
- 风险对象：
- 观众问题：
- 是否承接上一集：
- 关键视觉动作：
- 关键声音/台词：
- 本节拍结束时的变化：

### 反审查

- 我是否需要先听 20 秒解释才知道发生什么？
- 风险是否具体到“谁会失去什么”？
- 这一钩子是否来自前集因果或已建立规则？
- 若只有“震惊表情”“响铃”“敲门”，是否缺少真正后果？
- 画面是否在手机上可一眼读懂？

---

## 节拍 2：当前问题与目标

### 目的

将异常转换为主角的可执行目标。

### 填写

- 主角此刻要什么：
- 成功的可见标准：
- 失败的可见代价：
- 谁/什么阻止：
- 主角初始策略：
- 为什么不采用更简单方案：
- 对手/系统此刻想要什么：

### 红线

不要写：

```text
主角要“查清真相”
主角要“改变命运”
主角要“获得幸福”
```

应写：

```text
主角要在电梯下到一楼前，抢回被对手拿走的门禁卡。
```

---

## 节拍 3：行动与反制

### 目的

主角不是被剧情推着走，而是采取可失败的行动。

### 填写

- 主角行动：
- 对手/环境阻碍：
- 主角如何调整策略：
- 可见资源变化：
- 关系权力变化：
- 对手如何因主角行动而反制：
- 本节拍结束时主角得到/失去什么：

### 最小行动规则

单集优先只承载：

```text
一个主体目标
一个主要行动
一个关键阻碍
一个状态转折
```

如果需要写：

```text
追车、打架、报警、查证、揭露身份、求婚、逃跑、失忆恢复
```

全部发生在同一集，应拆分或删减。

---

## 节拍 4：转折与后果

### 目的

让本集不是“差一点成功”，而是真正改变状态。

### 填写

- 本集转折：
- 转折前主角理解：
- 转折后主角理解：
- 新资源或资源损失：
- 新关系状态：
- 新风险：
- 对下一集的直接影响：

### 有效转折类型

- 目标变更；
- 权力反转；
- 关系从合作变对抗，或反之；
- 关键信息改变行动；
- 资源易主；
- 时间窗口缩短；
- 人物做出不可逆选择；
- 旧规则被证实或被重新理解。

### 无效转折

- 角色只是更生气；
- 同一争吵音量更大；
- 新角色进来重复旧信息；
- 随机事故暂时打断；
- 角色知道一个与当前行动无关的设定；
- 梦、误会或回忆取消此前风险。

---

## 节拍 5：集尾钩子

### 目的

不是中断，而是由本集状态变化产生明确的下一步问题。

### 钩子公式

```text
本集人物选择 / 本集反转
+ 不可忽略的后果
+ 尚未确定的结果
= 集尾钩子
```

### 填写

- 触发钩子的本集行动：
- 已发生的状态变化：
- 下一集必须回答的问题：
- 观众已经知道什么：
- 观众还不知道但合理期待什么：
- 下一集前 20 秒提供的初步回报：
- 1–3 集内的完整回报：
- 若存在付费点：即将兑现的价值：

### 钩子类型

| 类型 | 适用情形 | 示例骨架 |
|---|---|---|
| 不可逆选择 | 人物必须承担后果 | 主角签下协议，却发现附页写着盟友的名字 |
| 关系翻转 | 忠诚或权力改变 | 盟友接到命令，必须抓捕主角 |
| 真相重构 | 新信息改变前文意义 | 证据指向主角自己 |
| 资源转移 | 关键物易主或失效 | 唯一备份被公开发送 |
| 迫近威胁 | 明确目标与时限 | 倒计时开始，目标就在下一地点 |
| 道德两难 | 两个选择都有代价 | 救亲人必须出卖盟友 |
| 计划反噬 | 成功暴露更大风险 | 主角逼对手承认，却暴露证据来源 |

### 默认无效钩子

```text
电话响起
有人敲门
角色突然晕倒
黑衣人出现
“你居然是……”
角色瞪大眼睛
门即将打开
切黑并写“未完待续”
```

除非它们已经具备明确前因、人物选择和可见后果。

# 10. 对白与字幕

## 对白原则

竖屏短集不等于每个人都说短句。

有效对白应：

- 改变关系、信息、权力或下一步行动；
- 适合近景中的表演；
- 让人物声音不同；
- 能被字幕清楚承载；
- 尽量让一句话只承担一个行动；
- 留出反应、停顿、眼神和关键动作空间。

避免：

```text
长段背景说明；
所有人物都说“金句”；
用台词解释画面已清楚表达的事；
用连续吼叫代替升级；
字幕过长且遮住关键脸部/道具。
```

## 字幕计划

| 段落 | 台词/声音信息 | 是否必须字幕 | 字幕长度风险 | 可否用动作替代 | 后期处理 |
|---|---|---|---|---|---|
|  |  |  |  |  |  |

## 无声观看测试

关闭声音后检查：

- 是否仍能看懂谁在行动；
- 是否仍能读到核心关系和风险；
- 是否有关键答案只存在于一句快速台词；
- 是否有关键动作被字幕或 UI 遮挡；
- 是否需要用表情、道具、屏幕图层或反应镜头补强。

# 12. 对抗式审查

## 怀疑观众

- 前 3–5 秒我看见了什么具体失衡？
- 前 10 秒我知道谁在乎什么吗？
- 我能否说出本集问题？
- 我在何处感到重复、解释过多或等待过久？
- 集尾是否让我明确知道下一集要看什么？
- 我是否会觉得被吸引，还是被强行截断？

## 逻辑检察官

- 每个事件能否以“因此/但是”连接？
- 主角有没有更合理却被剧本忽略的行动？
- 对手的反制是否与其资源、信息和目标相符？
- 人物是否知道不应知道的信息？
- 道具、服装、伤病、时间、地点与前后集是否一致？
- 钩子是否来自人物行动或已知规则，而非随机事故？

## 人物辩护人

- 主角是不是只被动遭遇？
- 本集是否迫使主角选择？
- 选择是否有代价？
- 对手是否有自己的目标和策略？
- 关系变化是否由行为支撑？
- 人物是否只会重复哭、吼、误会、求饶或震惊？

## 竖屏制片人

- 关键视觉是否在手机上可读？
- 主角脸、手、关键道具和情绪是否有明确优先级？
- 是否过度依赖远景、群像、小字 UI 或复杂调度？
- 是否可用更少地点、角色、道具达到同样效果？
- 镜头是否可拆为单一主体、单一动作、单一焦点？
- AI 制作是否能稳定维持角色、服装、道具与空间？

## 信任守门人

- 钩子是否承诺了不会兑现的内容？
- 是否延迟答案却没有初步回报？
- 是否把付费后内容写成无效拖延？
- 是否重复同一种身份反转、误会、失踪或羞辱？
- 是否为了集数让人物突然失智？
- 观众看完会觉得“想继续”，还是“被耍了”？

# 15. 锁定门禁
